# MediaCollector 公开后端设计

## 目标

建立一个可独立安装、运行和发布到 GitHub 的后端仓库，覆盖抖音和微博下载能力，不包含 Electron UI。

## 选择

采用单进程 FastAPI + 统一异步任务模型。抖音沿用成熟下载核心，微博沿用 MediaCollector 的分页、完整图片和 HLS 逻辑，由平台执行器隔离差异。

未采用两个独立服务的组合方式，因为它会重复配置、进程和状态接口；未采用只发布现有抖音仓库的方式，因为无法满足微博统一交付。

## 接口

- `POST /api/v1/downloads` 创建任务。
- `GET /api/v1/jobs/{id}` 查询任务。
- `GET /api/v1/jobs` 列出进程内任务。
- `GET /api/v1/health` 健康检查。

请求统一包含平台、URL、保存目录、日期和分页范围。平台特有选项保留为明确字段。

## 生命周期

应用启动时创建共享限流器、队列、Cookie 管理器、微博浏览器 Provider 和下载器。每个抖音任务复制配置，避免并发写共享状态。关闭时等待任务并释放 HTTP 和浏览器资源。

## 安全

- 默认监听回环地址。
- CORS 默认关闭。
- 可选 API Key；公网部署必须由反向代理提供 HTTPS、身份控制和限流。
- Cookie 只从环境变量或本地受保护文件读取，不返回、不记录。
- Git 忽略下载内容、Cookie、数据库、浏览器目录、模型和 UI 资产。

- FastAPI 能启动并提供统一 OpenAPI。
- 抖音既有测试和微博迁入测试通过。
- Ruff、编译、构建、敏感信息扫描通过。
